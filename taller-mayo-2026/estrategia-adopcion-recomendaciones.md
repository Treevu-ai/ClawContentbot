## 2️⃣ PERFIL IDEAL — "¿Para quién es esto?"

### ✅ ESTE TALLER ES PARA TI SI:

- [ ] Sos ejecutivo, emprendedor o profesional independiente con una idea de negocio validada o en validación
- [ ] Tenés experiencia usando herramientas digitales (Zoom, Google Workspace, navegadores) sin problemas
- [ ] Buscás reducir la brecha entre tu estrategia y la ejecución tangible
- [ ] Querés aprender a usar IA no como juguete, sino como herramienta de ejecución empresarial
- [ ] Tenés 2-3 horas semanales para dedicar entre sesiones
- [ ] Tu objetivo es lanzar una landing funcional para validar una oportunidad, no construir el próximo unicornio
- [ ] Preferís aprender haciendo (60% práctica) que escuchando teoría
- [ ] Entendés que la IA no reemplaza tu criterio, pero amplifica tu capacidad de ejecución
- [ ] Te sentís cómodo invirtiendo $97-197 en tu desarrollo profesional
- [ ] Buscás metodologías aplicables inmediatamente en tu organización o proyecto
- [ ] **No querés juegos:** buscás resultados concretos, dinámicas con propósito
- [ ] **No querés complicarte:** documentación justa y necesaria, no burocracia
- [ ] **Querés mantener control:** aprender a hacer, no depender de terceros

### ❌ ESTE TALLER NO ES PARA TI SI:

- [ ] Buscás aprender a programar desde cero (esto es "sin saber programar", no "sin tocar código")
- [ ] Esperás que la IA haga todo el trabajo sin tu involucramiento estratégico
- [ ] Ya tenés un equipo de desarrollo establecido y buscás escalar técnicamente
- [ ] Querés construir una aplicación compleja con base de datos, autenticación de usuarios, etc.
- [ ] No tenés una idea clara de qué querés validar (venís "a ver qué surge")
- [ ] Esperás resultados sin hacer el homework entre sesiones
- [ ] Tu presupuesto es limitado y esto representa un esfuerzo financiero grande
- [ ] Buscás certificaciones o títulos formales (esto es ejecución práctica, no académico)
- [ ] Creés que la IA va a reemplazar completamente tu criterio empresarial
- [ ] **Te incomoda mantener control:** preferís delegar antes que aprender a hacer
- [ ] **Te abruma la documentación:** no querés ni siquiera lo esencial organizado

### 📦 KIT DE EMERGENCIA (preparar ANTES del taller)

#### Cuentas y accesos:
- [ ] Crear cuenta Gmail para el taller: `iaworkshop@gmail.com` (o similar)
- [ ] Asociar cuentas en las herramientas principales a ese correo:
  - Claude.ai (Anthropic)
  - ChatGPT Plus (OpenAI)
  - Gemini Advanced (Google)
  - GitHub (para deploy)
  - Stitch / V0.dev (para diseño)
- [ ] Tener prompts equivalentes para cada herramienta
- [ ] Probar el flujo completo con Plan B (dry run de 30 min)
- [ ] Guardar screenshots de cada paso alternativo
- [ ] Preparar documento "Si X falla, hacer Y" para compartir en Sesión 0

#### Playbooks por sesión (CRÍTICO):
Para cada una de las 4-5 sesiones del taller, crear un playbook que incluya:
1. **Objetivo de la sesión** (qué deben lograr al finalizar)
2. **Herramientas requeridas** (con links directos y credenciales si es necesario)
3. **Pasos paso-a-paso** (screenshots + texto, nada ambiguo)
4. **Prompts exactos** a usar en cada etapa (copiar y pegar)
5. **Criterios de éxito** (¿cómo saben que lo hicieron bien?)
6. **Plan B** (qué hacer si la herramienta principal falla)
7. **Homework** (qué deben entregar antes de la siguiente sesión)

**Formato recomendado:** Google Doc o Notion, compartido con participantes antes de cada sesión.

#### Prompts de respaldo (ejemplo):
```
# Prompt para validación de entrevistas (si Claude falla)
# Usar con: ChatGPT-4 o Gemini Advanced

"Actuá como un experto en validación de startups. Voy a compartirte 
3 entrevistas que hice con potenciales usuarios. Analizá:
1. Patrones recurrentes en los problemas mencionados
2. Señales de disposición a pagar
3. Banderas rojas (The Mom Test)

Entrevistas: [pegar transcripciones]"
```

### 🎭 GUION PARA COMUNICAR FALLAS (si ocurren)

**Si hay downtime durante el taller:**

> "Chicos, [herramienta] está cayendo. Es parte de trabajar con 
> herramientas en la nube. Vamos a usar [alternativa] que hace 
> lo mismo. De hecho, esto es valioso: en el mundo real las 
> herramientas fallan, y saber adaptarse es parte del skill. 
> Los 15 minutos que tardemos en ajustar el plan son parte del 
> aprendizaje."

**Por qué esto es bueno:**
- Normaliza la falla (no es tu culpa)
- Convierte el problema en enseñanza
- Demuestra flexibilidad (skill que querés transmitir)

### 📄 DOCUMENTO A COMPARTIR CON PARTICIPANTES

Crear un `README.md` o Google Doc con:
- Links a todas las herramientas (A, B y C)
- Instrucciones de setup alternativo
- Tu contacto directo por si hay problemas técnicos
- Grabación de la Sesión 0 (para que puedan hacer setup después)

### 💡 Contexto para tu audiencia:
Dado que trabajás con ejecutivos y profesionales senior que valoran control sin burocracia:

1. **Playbooks claros > documentación extensa:** Cada sesión debe tener su guía paso-a-paso, pero solo lo esencial. Nada de manuales de 50 páginas.

2. **Cuenta dedicada (`iaworkshop@gmail.com`):** Esto te permite:
   - Gestionar accesos de participantes de forma centralizada
   - Recuperar cuentas si alguien se traba
   - Mantener consistencia en el entorno de trabajo
   - Separar tu uso personal del uso educativo

3. **Control sin dependencia:** El objetivo es que aprendan a hacer, no que dependan de vos. Los playbooks son andamios, no muletas permanentes.

4. **Plan B como estándar profesional:** Tu audiencia no tolera improvisación. Tener alternativas probadas no es opcional, es parte de tu propuesta de valor.

5. **Enmarcar fallas como aprendizaje:** Cuando algo falle, usalo como caso de estudio de gestión de riesgos. "Esto es lo que pasa en el mundo real. Así es como se responde."
